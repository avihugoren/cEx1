GPU basics · level 1b

A GPU is ten units, and each one has a single job

Some units bring work in, some do the math, and some move data. Learn them in that order. NVLink comes after this.

Example: NVIDIA H100 SXM5 · names follow NVIDIA’s H100 whitepaper

Unit by unit

What each unit does, in two sentences

1 · PCIe interface

The door to the CPU

Commands and data from the host arrive here. The CPU can also read GPU registers and memory through it.

Gen 5 ×16 · 64 GB/s each way

2 · Front end

Reads the to-do list

The driver writes commands into buffers in memory. The front end fetches them and hands work to the SMs.

Includes the work distributor

3 · Copy engines

Move big blocks of data

DMA engines that copy between host memory and GPU memory, or between GPUs. The SMs keep computing while they run.

What cudaMemcpy uses

4 · GSP + controllers

The firmware cores

Small processors that boot and manage the GPU: GSP (RISC-V) runs most of it; PMU, SEC2 and FSP handle power and security.

Where your firmware runs

5 · GPC → SM

Do the math

A GPC is a group of SMs. The SM (streaming multiprocessor) is the real core: it runs threads 32 at a time.

8 GPCs · 132 SMs enabled

6 · Crossbar

The internal switchboard

Connects every SM to every slice of the L2. Any SM can reach any address.

On-chip network

7 · L2 cache

Shared fast memory

Keeps recently used data close for all SMs. Every memory access, local or remote, passes through it.

50 MB

8 · Memory controllers + HBM

The big memory

Controllers read and write HBM: memory chips stacked next to the GPU. Large, fast, but slower than L2.

80 GB · 3.35 TB/s

9 · MMU

Translates addresses

Programs use virtual addresses. The MMU walks page tables to find the real location, and blocks access that is not allowed.

Page tables set up by the driver

10 · HSHUB + NVLink

The door to other GPUs

Sends traffic for another GPU’s memory out over NVLink. To the SMs, a peer GPU looks like more memory.

Inside the SM

Each SM is four small cores that share one fast memory

Warp scheduler

Picks what runs next

Holds many warps. When one waits for memory, it switches to another at once, so the lanes stay busy.

Register file

Each thread’s private variables

The fastest storage on the chip. 64 KB per partition, split among the threads that run there.

FP32 lanes · tensor core

The calculators

FP32 lanes do ordinary math, one lane per thread. Tensor cores multiply small matrices in one step.

L1 · shared memory

Fast memory for the SM

Part cache, part scratchpad that threads in one block use to share data.

Remember

Four things to keep in your head

  1. Top of the chip brings work in: PCIe, front end, copy engines. Firmware cores (GSP and others) manage the chip.
  2. The GPCs hold the SMs. An SM runs warps of 32 threads; a warp runs on one of its four partitions.
  3. Data moves SM → L1 → crossbar → L2 → memory controller → HBM. The MMU translates every address.
  4. NVLink is one more exit from the L2 side, to another GPU’s memory. That is the next lesson: Where NVLink code runs.
