NVLink for GPU firmware

One GPU reads another GPU’s memory with a plain load

NVLink carries ordinary memory reads and writes between GPUs. The MMU sends the address out a link, and the NVSwitch routes it to the GPU that owns it.

Numbers are for H100 SXM5 (NVLink 4) unless a figure says otherwise

GPU units

A GPU is many SMs around one shared L2, with I/O on the edges

GPC · TPC · SM

Where kernels run

A GPC holds 9 TPCs. A TPC holds 2 SMs. The SM is the core: it runs warps of 32 threads.

L2 cache

The meeting point

All SMs, copy engines and NVLink traffic meet here. Remote reads from other GPUs are served from it.

Memory controllers · HBM3

Local memory

Stacked DRAM next to the die, behind the L2. 80 GB at 3.35 TB/s on H100 SXM5.

Front end · copy engines

Takes work from the host

The front end reads command buffers (pushbuffers). Copy engines move bulk data, also over NVLink.

GSP and microcontrollers

Where firmware runs

The GSP is a RISC-V core that runs GPU management firmware. Other small cores handle power and security.

NVLink · PCIe

The two ways out

NVLink goes to other GPUs or switches. PCIe goes to the host CPU, NICs and storage.

Firmware on the GPU
  • GSP (GPU System Processor): a RISC-V core. Recent drivers move GPU init and management into firmware that runs here.
  • PMU: power and clock management. SEC2: security tasks. FSP on Hopper: secure boot and root of trust.
  • These names come from NVIDIA’s open-source kernel driver. Your team’s internal docs are the authority for what runs where.

Protocol

Three layers: the wire, the reliable link, and the memory transaction

Link states

Firmware brings a link up slow, trains it, then runs it fast

  1. ① Reset and calibrate. Power the SerDes, lock the PLLs, calibrate the receivers.
  2. ② Train in SAFE. Run training sequences, tune equalization, and align the lanes so bits arrive in order.
  3. ③ Go to HS. Set up the data link: starting sequence numbers and the credit count each side may use.
  4. ④ Watch it run. Read CRC, replay and recovery counters. Retrain or take the link down when a threshold trips.

Remember

Five things to keep in your head

  1. NVLink carries memory reads, writes and atomics. The page table decides whether a load goes to local HBM or across a link.
  2. A link is two one-way sub-links. Each flit is spread across all lanes of its sub-link.
  3. The data link layer hides bit errors: CRC finds them, the replay buffer fixes them, credits stop buffer overflow.
  4. Firmware brings each link up: calibrate, train in SAFE, run in HS, then watch the error counters.
  5. NVSwitch gives all-to-all bandwidth, and with SHARP it can also do the adding for an all-reduce.
