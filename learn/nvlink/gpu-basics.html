Start here · GPU basics

A GPU does one simple step on huge amounts of data at once

A CPU has a few strong cores. A GPU has thousands of simple lanes that all run the same instruction. AI and graphics are made of exactly that kind of work.

Example GPU: NVIDIA H100 · Level 1 of a series · no protocol detail yet

Main units

Six blocks do almost all the work

CPU host · PCIe

Gives the orders

Your program runs on the CPU. The driver sends the GPU commands and data over PCIe.

Front end

Reads the to-do list

It reads command buffers from memory and starts kernels: functions that run on thousands of threads.

SM · streaming multiprocessor

Does the math

The GPU’s core. Each SM runs many groups of 32 threads (warps) and has its own small fast memory.

L2 cache

Shared fast memory

One cache for the whole chip. Every SM reads and writes through it.

HBM

The big memory

Memory chips stacked next to the GPU. Large and fast, but slower than L2.

GSP · firmware

The GPU’s own small computer

A RISC-V core inside the GPU. It runs firmware that boots and manages the chip.

Why NVLink

One GPU is not enough, so GPUs must share data fast

Big AI models do not fit in one GPU, so the work is split across many GPUs. They must swap results all the time. PCIe is too slow for that. NVLink is a direct, much faster path between GPUs.

NVSwitch

A switch lets every GPU talk to every other GPU at full speed

Your layer
